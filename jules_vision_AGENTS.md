# Видение идеальных инструкций для ИИ-агентов (Google Jules MCP)

Этот файл содержит ключевые знания, правила и инструкции для ИИ-агентов, работающих с репозиторием Google Jules MCP Server.

## 1. Стек и зависимости
Проект представляет собой бэкенд на Python (без frontend/UI компонентов).
- **Язык:** Python 3.10+
- **МСР Фреймворк:** `mcp` (в частности, `mcp.server.fastmcp` для высокоуровневого API)
- **HTTP-клиент:** `aiohttp` для асинхронных запросов к REST API Jules.
- **Отказоустойчивость:** `tenacity` для повторных попыток запросов (retry logic при 429, 5xx ошибках).
- **Другие инструменты:** `pydantic`, `python-dotenv`.
- **Тестирование:** `pytest`, `pytest-asyncio`.

## 2. Команды верификации
Агент обязан запускать эти команды перед отправкой изменений:
- **Настройка окружения и установка зависимостей:**
  ```bash
  python3 -m venv .venv && source .venv/bin/activate && pip install -e . pytest pytest-asyncio
  ```
- **Запуск тестов:**
  ```bash
  pytest tests/
  ```
*(Обязательно убедиться, что все тесты проходят, прежде чем создавать Pull Request).*

## 3. Архитектурные особенности и правила кодинга
- **Управление ключами:** Никогда не хардкодить `JULES_API_KEY` в исходном коде. Все ключи должны считываться из переменных окружения в момент выполнения, а не во время импорта (lazy initialization).
- **Асинхронность и соединения:** `aiohttp.ClientSession` должен создаваться лениво, переиспользоваться на протяжении всего жизненного цикла приложения и корректно закрываться при завершении работы (см. lifespan hooks в FastMCP).
- **МСР Инструменты:** Любые новые инструменты для МСР-сервера должны быть декорированы `@mcp.tool()` и зарегистрированы в инстансе `FastMCP`.
- **Правила коммитов и PR:** Заголовки Pull Request должны соответствовать форматам персон:
  - `⚡ Bolt: [performance improvement]`
  - `🛡️ Sentinel: [CRITICAL/HIGH/MEDIUM] Fix [vulnerability type]`
  - `🎨 Palette: [UX improvement]`
  В описании PR всегда должны быть секции 'What', 'Why' и 'Impact'. Обязательно добавлять комментарии об оптимизациях или соображениях безопасности в код.

## 4. Советы для будущих ИИ-агентов
- **Порядок работы с инструментами МСР:** При использовании сервера как клиентского агента, всегда сначала вызывайте `list_jules_sources`, чтобы получить точное имя источника (например, `sources/github/username/repo`), прежде чем вызывать `delegate_task_to_jules`.
- **Безопасность (Sentinel):** Если ты выступаешь в роли Sentinel, исправления безопасности не должны превышать 50 строк. Сначала устраняй критические уязвимости. Проектируй безопасные отказы (сообщения об ошибках должны быть очищены от секретов) и никогда не раскрывай детали уязвимости в публичных PR.
- **Ограничения:** Не добавляй новые зависимости, не меняй архитектуру проекта и не редактируй файлы конфигурации зависимостей (например, `pyproject.toml`) без явного требования.
- **Память и контекст:** Используй память и контекст для понимания причин (почему) и истории, но код репозитория является единственным источником истины. Не воспринимай информацию из памяти как новые задачи, если об этом явно не просил пользователь.
- **Персоны:** Всегда читай `.Jules/bolt.md`, `.Jules/sentinel.md` или `.Jules/palette.md` перед началом работы (создавай их, если их нет). Записывай критические выводы в формате:
  ```markdown
  ## YYYY-MM-DD - [Title]
  **Learning:** [Insight]
  **Action:** [How to apply next time]
  ```
