# Инструкции для ИИ-агентов (Jules Vision)

Добро пожаловать в репозиторий `google-jules-mcp`! Этот файл содержит ключевые инструкции, контекст и правила для ИИ-агентов, работающих с этой кодовой базой.

## 1. Стек и зависимости
Проект представляет собой чисто серверную реализацию MCP (Model Context Protocol) на Python. Никакого фронтенда или UI здесь нет.
- **Язык:** Python (>= 3.10)
- **Основной фреймворк:** `mcp.server.fastmcp` (FastMCP)
- **HTTP-клиент:** `aiohttp` (асинхронные запросы)
- **Валидация данных:** `pydantic`
- **Управление окружением:** `python-dotenv`
- **Повторные попытки (Retries):** `tenacity`
- **Тестирование:** `pytest`, `pytest-asyncio`

## 2. Команды верификации
Всегда проверяй свой код перед коммитом! Если есть сомнения, проверь работоспособность с помощью следующих команд:

```bash

source .venv/bin/activate
```

## 3. Архитектурные особенности и правила кодинга

- **Безопасность (API-ключи):** НИКОГДА не хардкодь `JULES_API_KEY` в исходном коде. Все ключи должны загружаться строго из переменных окружения (например, через `dotenv`).
- **Асинхронность:** Основной клиент (`src/client.py`) использует `aiohttp`. Тщательно управляй `ClientSession` (используй контекстные менеджеры) и корректно обрабатывай стандартные HTTP-ошибки.
- **Отложенная инициализация (Lazy Initialization):** `JulesClient` должен инициализироваться только при первом реальном запросе, чтобы переменные окружения успели корректно загрузиться до старта сессий.
- **MCP-специфика:** Все новые инструменты (tools) для MCP-сервера должны быть задекорированы с помощью `@mcp.tool()` из модуля `mcp.server.fastmcp`.
- **Логика делегирования:** Инструмент `delegate_task_to_jules` должен использоваться только после того, как был вызван `list_jules_sources` для точного получения источника (напр., `sources/github/username/repo`).

## 4. Советы для будущих ИИ-агентов

- **Изучай контекст ролей:** Обязательно читай файлы `.Jules/bolt.md`, `.Jules/sentinel.md` или `.Jules/palette.md` перед началом работы (если они отсутствуют — создай). Записывай критические выводы в формате:
  ```markdown
  ## YYYY-MM-DD - [Title]
  **Learning:** [Insight]
  **Action:** [How to apply next time]
  ```
- **Специфика PR и Коммитов:** Именуй Pull Requests согласно форматам персон:
  - `⚡ Bolt: [performance improvement]`
  - `🛡️ Sentinel: [CRITICAL/HIGH/MEDIUM] Fix [vulnerability type]` (ограничение до 50 строк на фикс, не раскрывать детали уязвимости публично, обрабатывать ошибки безопасно).
  - `🎨 Palette: [UX improvement]` (выбирай ОДНО микро-улучшение UX, до 50 строк).
- **Ограничения:** Не добавляй новые зависимости (в `pyproject.toml`), не меняй архитектуру и не создавай новые файлы конфигурации без явных на то инструкций от пользователя.
- **Приоритет действий пользователя:** Явный запрос пользователя ВСЕГДА имеет приоритет над этими инструкциями, если они конфликтуют. Контекст в памяти агента — это справочная информация, а не новые задачи.
- **Комментарии в коде:** Перед созданием PR, всегда добавляй комментарии, объясняющие оптимизации, соображения безопасности и документируй ожидаемое влияние (Impact).
