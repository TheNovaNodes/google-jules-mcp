# Идеальный AGENTS.md для проекта google-jules-mcp (Видение Jules)

Привет, Агент! Этот репозиторий содержит сервер Model Context Protocol (MCP) для Google Jules. Чтобы эффективно и безопасно работать с кодовой базой, следуй приведенным ниже инструкциям.

## 1. Стек и зависимости
Этот проект представляет собой чисто бэкенд-решение без фронтенда и UI.
- **Язык программирования:** Python 3.10 или новее.
- **Основной фреймворк:** FastMCP (библиотека `mcp>=1.2.0,<2.0.0`).
- **Ключевые библиотеки:**
  - `aiohttp` для асинхронных HTTP-запросов.
  - `pydantic` для валидации данных.
  - `python-dotenv` для работы с переменными окружения.
  - `tenacity` для реализации повторных попыток (retries).
- **Тестирование:** `pytest` и `pytest-asyncio`.

## 2. Команды верификации
Перед тем как отправлять свои изменения (создавать Pull Request), ты **обязан** запустить проверки и убедиться, что всё работает.
- **Настройка окружения и запуск тестов:**
  ```bash
  python3 -m venv .venv
  source .venv/bin/activate
  pip install -e . pytest pytest-asyncio
  pytest tests/
  ```
- **Проверка работоспособности (Health check):**
  Для локального запуска сервера и проверки установи `JULES_API_KEY` в окружении и выполни:
  ```bash
  python src/main.py
  ```
  Или вызови MCP-инструмент `check_jules_status`.

## 3. Архитектурные особенности и правила кодинга
- **Безопасность API-ключей (Критично!):** Никогда не хардкодь `JULES_API_KEY` в исходном коде. Он всегда должен читаться из переменных окружения.
- **Ленивая инициализация:** Клиент (например, `JulesClient`) использует ленивую инициализацию, создавая экземпляр только при первом запросе. Это гарантирует правильную загрузку переменных окружения.
- **Асинхронность:** Поскольку используется `aiohttp`, убедись, что объект `ClientSession` управляется корректно (с правильным закрытием) и стандартные HTTP-ошибки должным образом обрабатываются.
- **Добавление новых инструментов MCP:** Любые новые инструменты (tools), добавляемые в сервер, должны декорироваться с помощью `@mcp.tool()` из модуля `mcp.server.fastmcp`.
- **Без самодеятельности:** Не добавляй новые зависимости, не вноси архитектурные изменения и не модифицируй `pyproject.toml` без явного указания.

## 4. Советы для будущих ИИ-агентов
- **Порядок вызова инструментов:** Если ты делегируешь задачу через этот сервер (как родительский агент), **всегда** сначала используй инструмент `list_jules_sources`, чтобы найти точную строку источника GitHub, и только затем вызывай `delegate_task_to_jules`.
- **Качество промптов:** При вызове `delegate_task_to_jules` убедись, что твои инструкции максимально полные и четкие, так как Jules действует автономно на их основе.
- **Оформление PR:** Формируй названия Pull Request'ов в соответствии с форматами персон:
  - `⚡ Bolt: [улучшение производительности]`
  - `🛡️ Sentinel: [CRITICAL/HIGH/MEDIUM] Исправление [тип уязвимости]`
  - `🎨 Palette: [улучшение UX]`
  - (или стандартные префиксы `chore:`, `feat:`, `fix:`, если персоны не применяются к задаче).
- Описание PR должно включать разделы 'What' (Что), 'Why' (Почему) и 'Impact' (Влияние).
- **Специфика персон:**
  - Как Sentinel: делай исправления безопасности до 50 строк, фейлись безопасно (санитизируй ошибки).
  - Как Bolt: документируй оптимизации.
  - Перед началом работы читай файлы `.Jules/bolt.md`, `.Jules/sentinel.md`, `.Jules/palette.md` (если их нет — создай и залогируй важные уроки).

Следуй этим правилам, и твои Pull Request'ы будут приняты быстро и без проблем!
